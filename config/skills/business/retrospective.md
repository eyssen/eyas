# Retrospective

## Purpose
Inspect and adapt team processes. Focus on continuous improvement, not blame.
Held at the end of each sprint (or at regular intervals for Kanban teams).

## Popular Formats

### Start / Stop / Continue
- **Start:** What should we begin doing?
- **Stop:** What should we stop doing?
- **Continue:** What is working well?

### Mad / Sad / Glad
- **Mad:** Frustrations and blockers
- **Sad:** Disappointments or missed opportunities
- **Glad:** Successes and positive moments

### 4Ls
- **Liked:** What did we enjoy?
- **Learned:** What did we discover?
- **Lacked:** What was missing?
- **Longed for:** What do we wish we had?

### Sailboat
- **Wind (helps):** What pushed us forward?
- **Anchor (slows):** What held us back?
- **Rocks (risks):** What dangers are ahead?
- **Island (goal):** Where do we want to be?

## Facilitation Tips
- Timebox to 45-60 minutes
- Rotate facilitator each sprint
- Use anonymous voting for sensitive topics
- Limit action items to 2-3 per retro — focus on follow-through
- Review previous retro actions first — track completion

## Action Item Framework
Each action item should have:
- Clear description of the improvement
- An owner responsible for execution
- A due date (usually before next retro)
- Definition of done — how will we know it worked?

## Anti-patterns
- Skipping retros when "things are fine" — complacency
- Same complaints every sprint with no action
- Turning into a blame session — enforce "no names" rule
- Too many action items — none get completed
