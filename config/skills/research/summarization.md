# Summarization

## Summary Types

### Executive Summary
- 1-2 paragraphs for decision-makers
- Focus on conclusions, recommendations, and impact
- No technical jargon unless audience expects it
- Lead with the most important finding

### Technical Summary
- Key architecture decisions and trade-offs
- Performance characteristics and limitations
- Dependencies and requirements
- Migration or integration considerations

### Bullet-Point Summary
- 5-10 key takeaways
- Each bullet is a self-contained insight
- Ordered by importance (most critical first)
- Include quantitative data where available

## Summarization Process
1. **First pass:** skim headings, introduction, and conclusion
2. **Second pass:** identify main arguments and supporting evidence
3. **Extract:** pull out key facts, figures, and quotes
4. **Synthesize:** combine into coherent summary in your own words
5. **Verify:** ensure summary accurately represents the source

## Length Guidelines
- Tweet-length (< 280 chars): single core insight
- Abstract (150-300 words): problem, approach, key findings
- Executive summary (1 page): full context with recommendations
- Detailed summary (2-5 pages): section-by-section breakdown

## Quality Checklist
- Does the summary stand alone without the original?
- Are all key points from the original represented?
- Is anything misrepresented or taken out of context?
- Is the summary proportionally balanced (main points get more space)?
- Would the original author agree with your summary?

## Common Mistakes
- Including too much detail (it's a summary, not a rewrite)
- Injecting personal opinion without labeling it
- Missing the main point while focusing on details
- Using the same structure as the original (reorganize by importance)
- Forgetting to cite the source
