# Proofreading

## Review Passes
Effective proofreading uses multiple focused passes:

### Pass 1: Content Accuracy
- Are all technical claims correct?
- Are numbers, dates, and versions accurate?
- Do code examples work?
- Are links valid?

### Pass 2: Structure and Flow
- Does the document follow a logical progression?
- Are transitions between sections smooth?
- Is the conclusion supported by the content?
- Is the right amount of detail in each section?

### Pass 3: Grammar and Style
- Subject-verb agreement
- Consistent tense (present for instructions, past for reports)
- Active voice preferred over passive
- Parallel structure in lists
- No dangling modifiers

### Pass 4: Consistency
- Terminology: same word for the same concept throughout
- Formatting: consistent heading levels, code formatting, list styles
- Capitalization: product names, technical terms
- Spelling: American vs. British English (pick one, be consistent)

### Pass 5: Final Polish
- Spell check (but don't rely on it alone)
- Read aloud for awkward phrasing
- Check widows and orphans in formatted output
- Verify table of contents and cross-references

## Common Technical Writing Errors
- "it's" vs. "its" (it's = it is, its = possessive)
- "affect" vs. "effect" (affect = verb, effect = noun usually)
- "e.g." vs. "i.e." (e.g. = for example, i.e. = that is)
- "which" vs. "that" (which = non-restrictive, that = restrictive)
- Comma before "and" in a series (Oxford comma — be consistent)

## Style Improvements
- Replace "utilize" with "use"
- Replace "in order to" with "to"
- Replace "at this point in time" with "now"
- Replace "a large number of" with "many"
- Remove "please" from technical instructions

## Feedback Format
When reviewing others' writing:
- Be specific: "Line 12: 'affect' should be 'effect'" not "check your grammar"
- Suggest alternatives, don't just criticize
- Distinguish must-fix from nice-to-have
- Praise what works well
