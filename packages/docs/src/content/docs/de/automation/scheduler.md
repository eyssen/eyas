Views List/Gantt/Calendar. Job: Name, Handler, Trigger Cron/Interval/Event, Agent ID + Prompt. Ein ungültiger Cron-Ausdruck oder ein Intervall unter einer Sekunde wird beim Erstellen abgelehnt, der Grund erscheint im Formular („Dieser Zeitplan ist ungültig, der Job würde nie laufen. Prüfen Sie den Cron-Ausdruck oder das Intervall.“); früher wurde ein solcher Job angelegt, lief aber stillschweigend nie. Ein **Event**-Trigger wird weiterhin akzeptiert, der Job startet dann aber nie von selbst und trägt die Kennzeichnung „Startet nie“. Run Now, Pause/Resume, Reschedule, Delete. Run Now ist nur dann deaktiviert, wenn der Job keinen registrierten Handler hat oder deaktiviert/dead-letter ist (Grund im Tooltip); ein Job mit der Kennzeichnung „Startet nie“ oder „Nicht eingeplant“ lässt sich weiterhin von Hand ausführen — bei einem Event-Job ist das die einzige Möglichkeit, ihn überhaupt auszuführen; Reschedule + Apply lehnt einen ungültigen Cron-Ausdruck oder ein Intervall unter einer Sekunde ab, der Grund erscheint unter dem Feld; ein Badge in der Zeile zeigt an, warum ein Job nicht laufen kann: „Kein Handler“ (nicht registriert — meist ist das Modul deaktiviert), „Startet nie“ (ein Trigger-Typ, bei dem der Job nicht von selbst startet) oder „Nicht eingeplant“ (ein Zeitplan, der nicht aktiviert werden konnte — ungültiger Cron-Ausdruck oder Intervall unter einer Sekunde); der Grund erscheint beim Überfahren des Badges mit der Maus. „Infrastruktur-Jobs anzeigen“ blendet einen nicht lauffähigen Job nie aus — ein defekter Systemjob bleibt auch bei deaktiviertem Filter sichtbar. In der Liste der letzten Ausführungen zeigt jede Zeile Startzeit, Dauer und wer sie ausgelöst hat (`system`, wenn ein Timer sie ausgelöst hat, ein Agent oder eine Benutzer-ID). Kinds: System handler / Agent routine. Health: Leader/Follower, active, running, failed 24h, dead-letter, overdue, N nicht lauffähig.
