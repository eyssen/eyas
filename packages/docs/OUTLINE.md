## How to read this book (Diátaxis, adapted)

Four jobs, one sidebar. We do **not** split the top level into Tutorials / How-to / Reference / Explanation — product handbooks (and in-app `?` targets) work better as a **learning path then product areas**. Each chapter still has a single primary job:

| Reader need | Lives here |
|-------------|------------|
| **Learn by doing** (tutorial) | Start: Getting started, Setup wizard, **Your first hour** |
| **Understand why** (explanation) | Core concepts + the *What this is for* lead on every chapter |
| **Get a job done** (how-to) | Daily work, Agents, Automation, Knowledge, Communication, AI, Admin |
| **Look up a fact** (reference) | Deploy & CLI, Glossary, FAQ, field tables at the bottom of how-to pages |

See `PAGE_TEMPLATE.md` for the chapter shape.

## Principles

1. **User journey first** — start → first hour → daily work → agents → automation → knowledge → channels → AI config → admin → deploy.
2. **Not 1:1 with every module** — group by task; each product surface still gets a chapter (no dumping Hands into Observability).
3. **Stable slugs** — used by `help-map.json` and in-app `?` links. Never rename a slug without updating the map and the UI.
4. **Architecture specs stay in repo `docs/`** — this package only points there.
5. **Every chapter opens with purpose** — what it is for, when to use it, a typical workflow; then features; then fields.
6. **Six locales** — en (source), hu, de, es, fr, tlh. Same relative path in each.
