Bevezetés Introduction

Mi az a Forge? What is Forge?

A Forge egy háromfázisú pipeline, amely folyamatosan és autónoman javítja az EYAS agensek eszközeit, skilljeit és promptjait — emberi kontroll mellett. Forge is a three-phase pipeline that continuously and autonomously improves EYAS agents' tools, skills, and prompts — under human control.

Phase 1
Observe

Strukturált visszajelzés minden eszköz- és skill-használat után. Hasznos volt? Volt súrlódás? Van jobb megközelítés? Structured feedback after every tool and skill usage. Was it useful? Was there friction? Is there a better approach?

Phase 2
Forge

Agens-vezérelt elemzés: súrlódási minták aggregálása, javítási javaslatok generálása, tesztelés sandbox környezetben. Agent-driven analysis: aggregate friction patterns, generate improvement proposals, test in sandbox environment.

Phase 3
Adopt

A felhasználó jóváhagyja, a változás élesítésre kerül, az agens memóriája rögzíti a „miért”-et. User approves, the change is applied, the agent's memory records the "why".

Előnyök Advantages

Legfontosabb megkülönböztető jegyek Key Differentiators

🧠

Agent Intelligence

Az agens érti, MIÉRT nem működött valami — nem csak azt, HOGY nem működött. Az érvelés-alapú megközelítés célzott javításokat tesz lehetővé. The agent understands WHY something failed — not just that it failed. Reasoning-based approach enables targeted improvements.

⏱

Real-time

A visszajelzés folyamatosan gyűlik, nem batch-ben. Amint mintazák jelennek meg, azonnal javaslat készül. Feedback is collected continuously, not batched. As soon as patterns emerge, proposals are generated immediately.

🔗

Unified

Ugyanaz a pipeline kezeli a skilleket ÉS az eszközöket. Nem külön rendszer, nem külön workflow. Same pipeline handles skills AND tools. No separate system, no separate workflow.

🧪

Sandbox Testing

A javaslatok izolált beszélgetésekben tesztelődnek delegálással, mielőtt élesbe kerülnének. Proposals are tested in isolated conversations via delegation before going live.

🐘

Memory-Backed

Minden fejlődési döntés az agens epizodikus memóriájában tárolódik. Az agens „emlékszik”, miért változott valami. Every evolution decision is stored in the agent's episodic memory. The agent "remembers" why something changed.

🔒

User Control

Minden változás jóváhagyást igényel. Teljes átláthatóság: látod az indokot, a diff-et, és a teszt eredményeket. Every change requires approval. Full transparency: you see the reasoning, the diff, and the test results.
