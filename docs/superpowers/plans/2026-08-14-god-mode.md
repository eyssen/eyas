# God Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Parallel multi-model ensemble on a conversation (God Mode): isolated workers, one-round cross-review, winner workspace promoted, unique insights listed, plus Settings roster and an Observability comparison tab.

**Architecture:** New `src/modules/agent/god-mode/` submodule. Separate `conversations.god_mode` boolean (not a fourth `orchestration` value). Workers are hidden child conversations (`god_mode = 0`) with isolated cwd. UI switch lives inside the Orchestration control. Reports extend Observability; no new nav item.

**Tech Stack:** TypeScript / Bun / Vitest / Drizzle runtime DDL / Hono `/api/v1` / React 19 + existing shadcn / i18next (en hu de es fr tlh) / CSS variables per theme.

**Spec:** `docs/superpowers/specs/2026-08-14-god-mode-design.md`

## Global Constraints

- MIT-compatible dependencies only — add **no** new package unless the license is checked and it is MIT/BSD/ISC/Apache-2.0.
- English code and comments; every user-facing string in all six locales (`en`, `hu`, `de`, `es`, `fr`, `tlh`).
- CSS variables only — `--god` / `--god-foreground`; never hardcoded gold; never reuse `--primary` or `--destructive` for God.
- `/api/v1/` prefix; CASL on every route (`manage Model` for config, `read`/`update Conversation` for runs, `read AuditEntry` for reports).
- Do **not** reuse `propose_team` / `team-driver`. Do **not** add `god` to the `orchestration` enum.
- Do **not** auto-merge code or auto-apply insights. Do **not** auto-resume crashed runs.
- Do **not** commit unless the user explicitly asks — skip every Commit step until then.
- `bun test <path>` for Vitest. Expected FAIL/PASS as written.

```ts
const b = { id: 'b', providerId: 'xai', modelId: 'grok' }

function body(over: Record<string, unknown> = {}) {

    costCeilingUsd: null,
    workspaceRetentionHours: 72,
    ...over,
  }

    const r = validateRoster(body(), { min: 2, max: 5 })
    expect(r.ok).toBe(true)
  })

  it('rejects fewer than min', () => {

    expect(r.ok).toBe(false)
    if (!r.ok) expect(r.error).toMatch(/at least 2/i)
```

### Task 9: Isolation — choose, fork, promote, GC

**Files:**

**Interfaces:**
- Consumes: `isGitRepo` from `@modules/tools/working-directories.js` (already imported by `orchestrator.ts`)
- Produces:

```ts
export function chooseIsolation(sourceDir: string | null): GodModeIsolation
export function workerTreePath(runId: string, slotId: string): string
// returns `.eyas-god/<runId>/<slotId>` under the source parent, or under os.tmpdir() when isolation is none (unused)

export function forkWorkerTree(opts: {
  sourceDir: string
  runId: string
  slotId: string
}): { isolation: 'worktree' | 'copy'; workspacePath: string; branch?: string }

export function promoteChangedFiles(opts: {
  workspacePath: string
  destDir: string
  isolation: 'worktree' | 'copy'
}): { copied: string[] }

export function gcGodWorkspaces(opts: {
  olderThanMs: number
  now?: number
}): { removed: number }
```

`chooseIsolation`: `null`/empty → `'none'`; `isGitRepo(sourceDir)` → `'worktree'`; else `'copy'`.

Fork worktree: `git worktree add -b god/<runId>-<slotId> <path> HEAD` from `sourceDir`. Fork copy: recursive copy excluding directory names `node_modules`, `.git`, `dist`, `__pycache__`, `.venv`, `.eyas-god`, `.eyas-worktrees`.

Promote: compute relative paths that differ from `destDir` (worktree: `git -C workspace diff --name-only` + untracked `git ls-files --others --exclude-standard`; copy: walk and compare mtime/size/hash). Copy those files onto `destDir`, creating directories. Never `git merge`. Never leave the `god/*` branch checked out on `destDir`.

GC: delete `.eyas-god/*` trees older than `olderThanMs` (mtime of the run directory) and `git worktree remove --force` + `git branch -D` for `god/*` branches whose directory is gone. Safe on non-repos.

`start` algorithm (lock this, do not invent another):

1. If `hasActiveRun(conversationId)` throw `GodModeBusyError`.
2. `validateRoster(store.getConfig(), { min, max, liveKeys })`. Failure → throw `GodModeConfigError` with the message (do not create a run).
3. `estimateGodModeCost`; if `costCeilingUsd != null` and estimate > ceiling → throw `GodModeCeilingError`.
4. Insert run `preparing`, snapshot roster, `chair_participant_id`, `isolation = chooseIsolation(source)`, insert participants `pending`.
5. Skip any participant whose `provider/model` is not in `liveKeys` (`skipped`). If remaining live `< min` → status `failed`, error `not enough live models`, return.
6. Fork (if not `none`). Fork failure on a slot → that participant `failed`.
7. For each live slot: `createSubConversation({ title: \`God ${modelId}\`, goalDescription: userText, parentConversationId, initialStatus: 'idle' })` then `update(child.id, { providerId, modelId, godMode: false, workingDirectories: workspacePath ? [workspacePath] : [], orchestration })`. Store `child_run_id = child.id`. Status `running`.
8. Set run `racing`. `Promise.all` `runConversation(child.id, runConversationDeps)` for live slots. On throw → participant `failed` (keep cost if the runner recorded any). On success → `completed`, copy tokens/cost/duration/summary from the child.
9. Mid-loop: if `store.sumCost(runId) > ceiling` → cancel unfinished (do not start remaining; if already running, the runner’s existing cancel path — call whatever `conversation-runner` uses for user cancel; if none, leave them and only skip new work). Then continue to review with whoever `completed`.
10. Survivors: if 0 → `failed`. If 1 → that winner, skip review, go to promote. If ≥2 → status `reviewing`. For each survivor, call `gateway.complete` (non-stream) with a prompt containing the other summaries + `git diff` (or file list when copy) and “reply with a single JSON object matching {voteFor, scores, uniqueInsights, risks, summary}”. `parseReviewJson`; null → discard vote. Persist review fields on the participant. **Do not** invoke `runConversation` for review (one shot, no tools).
11. `tallyVotes` + `harvestInsights`. Persist winner, `tie_broken`. Status `deciding` then `promoting`.
12. If isolation ≠ none: `promoteChangedFiles`. On throw: leave status `completed` but set `error = 'promote failed: …'` so retry works. Copy winner child’s last assistant message onto the parent via `conversations.addMessage`.
13. Status `completed`, `completed_at = now`, roll up totals.

`failInFlightGodRuns`: `UPDATE god_mode_runs SET status='failed', error='process restarted', completed_at=now WHERE status IN ('preparing','racing','reviewing','deciding','promoting')`. Return changes count. Do not delete trees (retention/GC handles them).

`hasActiveRun`: any run on that conversation whose status is not `completed|failed|cancelled`.

Routes (permission `read Conversation` for GET, `update Conversation` for POST):
- `GET /api/v1/conversations/:id/god-mode/runs` → `{ runs }` (include participants)
- `GET /api/v1/god-mode/runs/:id` → `{ run, participants, insights }` (`insights` from stored unique_insights harvested at decide time — persist them as JSON on the run: add column `insights TEXT` via ALTER in `ensureGodModeSchema` and the contract test)
- `POST /api/v1/god-mode/runs/:id/cancel`
- `POST /api/v1/god-mode/runs/:id/promote` — `retryPromote`

Also add `GET /api/v1/god-mode/estimate?conversationId=` (read Conversation) returning `{ usd, ceilingUsd, participants }` so the banner can show `~$X` without starting a run.
