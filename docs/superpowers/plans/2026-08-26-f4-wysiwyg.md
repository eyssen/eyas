# F4 — WYSIWYG & Interactive Prototypes Implementation Plan

**Goal:** Select an element on an artboard, change it in a properties panel, edit its text in place, flip its tweak chips, and undo — with every change landing back in the `.dc.html` source.

## The constraint that shapes everything

The artboard renders in a `sandbox="allow-scripts"` iframe with **no `allow-same-origin`**, and that is not negotiable — it is the only reason executing AI-authored JavaScript is acceptable at all. Consequently **the parent page cannot touch the artboard's DOM.** Selection, highlighting, style edits and text edits all have to cross a `postMessage` boundary.

That inverts the usual design. The obvious approach — parse the template in the app, mutate it, re-render — needs a DOM parser server-side and a way to map a rendered node back to its source node. Instead:

> **The runtime owns the template DOM and the mutation.** It tags every template
> element with a stable index at parse time, carries the index onto the rendered
> element, applies an edit to its own template copy, re-serialises, re-renders,
> and posts the new source back. The app splices that body into the `.dc.html`
> file and stores it.

One parser, in one place, and no rendered-to-source mapping problem.

**Message trust.** Messages arrive from an opaque origin (`"null"`) and are as untrusted as the artboard itself. The parent verifies `event.source === iframe.contentWindow`, validates every message against a strict shape, and never renders or executes anything from a message outside the same sandbox. The worst a hostile artboard can do is rewrite its own source, which is what an editor is for.

## Task list

| # | Task | Files | Acceptance |
|---|---|---|---|
| 1 | **Editor protocol + runtime editing** | `dc-runtime-source.ts`, `dc-edit-protocol.ts` | Elements carry a stable source index; click posts a selection with its inline styles and tag; a style patch mutates the template and posts back new source; a text patch does the same; re-render preserves selection |
| 2 | **Source splicing** | `dc-splice.ts` | Replaces the `<x-dc>` body in a `.dc.html` file, preserving helmet, the logic script and the head marker; patches a `data-props` default in place; refuses anything that would not re-parse |
| 3 | **Selection + properties panel** | `pages/design/properties-panel.tsx` | Typography, colour, spacing, border, radius and layout; grid tracks round-trip through `repeat(N, minmax(0, 1fr))`; edits apply live |
| 4 | **Inline text editing** | runtime + panel | Double-click a text node to edit in place; Escape cancels; blur commits |
| 5 | **Tweak chips** | `pages/design/tweak-chips.tsx` | `data-props` editors render as controls above the frame; a change re-renders live; saving writes the value as the new default |
| 6 | **Undo/redo + save** | `design-detail-page.tsx` | Per-artboard stack, Cmd/Ctrl+Z and Shift+Z; explicit save writes one version, not one per keystroke |
| 7 | **`is_interactive`** | canvas + panel | An artboard with working controls is marked in `canvas.json` and rendered without the click-to-select overlay so its own handlers work |
| 8 | **Docs** | architecture, CHANGELOG, doc pages | No `full-docs` run |

## Exit criteria

1. Test and lint at baseline; six locales.
2. A style edit made in the panel appears in the stored `.dc.html` and survives a reload.
3. The iframe still has `allow-scripts` and never `allow-same-origin` — asserted.
4. A message from a window that is not the artboard's own iframe is ignored — asserted.
5. Undo restores the previous source exactly; save produces exactly one version.
6. An `is_interactive` artboard's own click handlers still fire.
